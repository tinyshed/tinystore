# Alibaba clock and metadata follow-up

Same corpora and baseline as [Alibaba](alibaba-2026-09-21.md) and
[TSBS](tsbs-2026-09-21.md): 12431885 and 5090400 samples respectively.
Ryzen 7 7700, Docker linux/amd64, Go 1.27.1, modernc SQLite 1.59.0,
klauspost/compress 1.19.0. No new dependency or production format change.

## The clock is mostly regular, even though most blocks are not

Alibaba has only 17.3% completely regular blocks, but **99.0628% of all adjacent
timestamp deltas are exactly 10000 ms**. Another 0.5052% are 20000 ms. There are
1108 different positive deltas, all divisible by 10000 ms. A few holes per
240-sample block explain the apparently contradictory figures.

The prototype compares three exact timestamp streams: deltas divided by their
GCD, runs of identical divided deltas, and a dominant delta plus gap-coded
exception positions and replacement deltas. Each can use zstd when smaller.
The value codec sees sample ordinals rather than physical timestamps. An
outer envelope holds the clock stream length and checksum binding the original
head to both streams. Those extra bytes are included. If the completed block
is not smaller, the previous grid encoding is retained.

Alibaba payload: **0.428244 → 0.346639 B/sample**, 42830 winning blocks.
TSBS: unchanged at 0.577471, with zero clock candidates selected. Baselines
include the grid wrapper; they are not the plain-codec values in split_spike.

## Compact grouped metadata

The previous group directory wrote ten fixed-width uint64 columns and zstd
over them. The new directory represents time by a shared quantum, gap from
the previous block's end, and span; payload offsets are implicit in lengths.
Count and length are varints. Summary values and the first value use an exact
tagged integer or hundredths representation when it round-trips bitwise,
otherwise their original eight bytes. The directory is checksummed and zstd
compressed. Every microblock keeps its own min/max/sum/last summary and head.

Payloads remain independent at at most 240 samples per decode. Groups combine
their bodies without compressing across microblock boundaries, and retain a
parent summary and the same per-series retention state and minimal registry.

experiment, not a tested ingest/retention implementation.

## What remains between us and VM

The prior VM Alibaba directory was 6338675 bytes (0.5099 B/sample), so the new
prototype is still 493453 bytes larger, about 7.8%. The measured reduction of
our file is 25.9%. On TSBS the prototype's 0.980871 is below VM's reported
1.0774, but that corpus's VM HTTP round trip did not preserve all original bits.
Neither comparison establishes a general engine win; VM cache bytes remain a
substantial part of the reported full-directory totals.

There is another measured redundancy: Alibaba's **1240 series have exactly
248 distinct full timestamp vectors**, confirmed by hash and complete equality.
That is the five metrics per machine repeating their clock. Across microblocks,
the new serialized clocks total 521570 bytes, with 103238 unique bytes; dedup
could remove 418332 bytes *before charging references, rows and lifecycle*.
This is an upper-bound opportunity, not another achieved file reduction.
Sharing a longer immutable clock segment, rather than creating one tiny SQLite
clock row per microblock, is the next architecture candidate. Random access
needs checkpoints; deletion needs atomic ownership/reference accounting.

Integrating the new time representation into the codec would also remove the
prototype's seven-byte outer envelope on selected blocks. Its standalone cost
is 299810 bytes on Alibaba, about 0.0241 B/sample. This is arithmetic, not a
predicted file saving: final codec selection and page packing must be rerun.

## Corrections to the preceding interpretation

NAB 3.1036 is real and documented in grid-2026-09-21.md: it follows the newer
residual modes and sixteen decimal scales, not the older grouped prototype.

Encoding real values and then constants and subtracting the two compressed
sizes is a useful intervention, not an exact byte attribution when timestamps
and values share zstd and candidate selection. Nor does our values estimate
being below VM's total data imply VM's own values cost at least as much as ours.
The clock improvements here are established by complete encoded and persisted
round trips, independently of that attribution.

## Limits and reproduction

No WAL, incremental ingest, retention, cold reads, latency distributions or RSS
were measured in this round. The file probe reads whole group payloads; it does
not integrate the prior incremental-BLOB prototype. Group reclamation is
coarser and the compact directory parser is research code, not a fuzzed public
decoder. No production source file was changed in this round.

```powershell
docker run --rm -m 6g -v <repo>:/src -v <corpus>:/corpus -v tinystore-gocache:/go -w /src -e TINYSTORE_JSONL=/corpus/series.jsonl -e GOCACHE=/go/build-cache golang:1.27 go test ./spike -run '^TestClockAndMetadataOnCorpus$' -v -count=1
```

Repeat with the `tinystore-tsbs` corpus directory for the TSBS check. The new
probe is `spike/clock_spike_test.go`. Normal tests and spike lint also pass;
full `task check` was not run.
