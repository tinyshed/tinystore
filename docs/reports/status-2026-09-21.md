# Status of TinyStore, for an architecture review

A historical snapshot taken **before the packed head**, and kept for the
comparison baseline. The engine update and the new TSBS run are in
[packed-head-2026-09-21.md](packed-head-2026-09-21.md): TSBS is now 1.078234
bytes a sample rather than the 2.509709 below. The older results are kept as
history; the Alibaba run was not repeated.

## The short answer

**The full target architecture is not implemented, and the working engine does
not yet reproduce the best densities of the research prototypes.**

A first end-to-end metrics engine exists: Open → Ingest → Read → Maintain →
Close → Open again, over a real SQLite file, with a label index, an exact head,
sealing, shared clocks, several value encodings and retention. That is library
code, independent of `spike/`, but it is neither the whole product nor grounds
for claiming a production win over VictoriaMetrics.

The repository base is `9e34181`. When this report was written the
implementation and the research material were still an uncommitted working
tree, with no tag and no CI run of that state; the checks listed below were
local. That tree has since landed on `main`.

## 1. Which numbers belong to what

Every figure is bytes per input sample. TinyStore is measured as whole SQLite
files. The main VictoriaMetrics column is the previously measured full
directory, caches included. Prometheus and VictoriaMetrics were not re-run for
this stage.

| Corpus | Best research TinyStore | Real metrics engine | VM, full directory | Prometheus |
|---|---:|---:|---:|---:|
| Alibaba, 12431885 samples | **0.360776** | **0.733083** | 0.5099 | 0.8577 |
| TSBS, 5090400 samples | **0.966387** | **2.509709** | 1.0774 | 1.6307 |

A qualification on TSBS: the single combined prototype produced 0.970410, while
0.966387 was the previous best variant with merged payloads. Those are two

What follows from that:

  larger than Prometheus**.
- "We beat VM on Alibaba" applies only to the previously measured full VM

  the current engine.
- Even against the prototype, VM without caches is more compact: Alibaba data

## 2. Why the prototype and the engine disagree

The prototype built sealed objects directly. The working engine first records a
mutable head, then moves only the safe prefix out of it. It also stores
postings, versions, frontiers, migrations and other bookkeeping.

TSBS shows this most clearly: 2020 series of 2520 samples each. At that load
2400 are sealed and the remaining 120 per series stay in the head. That is
242400 uncompressed head points. They are neither discarded nor declared
immutable to improve the number.

The real TSBS file, divided:

| Object | Bytes |
|---|---:|
| head | **6402048** |
| payloads | 3076096 |
| series | 1011712 |
| unique series index | 1011712 |
| postings | 663552 |
| groups | 409600 |
| series_state | 77824 |
| series_due | 36864 |
| other b-trees from dbstat | 24576 |
| the whole file beyond the dbstat pages above | 61440 |
| **Total** | **12775424** |

The head table alone is roughly half the file. The current label canonicalisation
and its index are also heavier than the compact registry of the benches. TSBS
effectively uses a single shared clock.

The 61440-byte remainder is not attributed to any structure: dbstat was taken
before Close and the physical size after it, and the freelist was not recorded
separately for this run. The remainder is counted in the total rather than
subtracted from the engine's size.

For Alibaba the per-object division of that particular engine run was not kept,
so attributing the whole gap to the head would be a guess. For either corpus it
is equally wrong to subtract these obligatory parts from the file and present
what is left as an engine scoreboard.

## 3. What is actually implemented

### Boundaries

- `metrics/`: the public types and the metric lifecycle.
- `internal/sqlite/`: connections, query-only readers, the writer, transactions,
  file identity and checked migrations.
- `codec/`: the existing, independently usable block codec.
- `spike/`: historical research benches, not an engine dependency.

Records, KV and the SQL mapper were not created as empty scaffolding and take no
part in metrics. There is no universal object or kernel framework.

### Writing and querying

- An atomic bounded batch, including series creation and postings.
- Canonical labels, equality matchers, cardinality and size limits.
- Bit-exact float storage in the head, including `-0`, NaN payloads and infinities.
- Last value wins for a duplicate timestamp in the mutable head.
- A refusal on write behind the retention cutoff or the persisted sealed frontier.
- A `[from,to)` read with logical retention clipping and no hidden downsampling.
- Registry, head, directories, clocks and payloads read from one snapshot.
  Values are decoded after it closes.
- Separate limits on matched series, bytes, blocks, decoded and output samples,
  and snapshot time; an error never comes with a partial answer.
- Close stops accepting operations and waits for the queries already admitted.

### Encoding and layout

- Independent microblocks of up to 240 samples, in groups of up to 32 slots.
- A bound on a block's event-time span, and size limits per object.
- Shared clocks checked by hash and by full comparison; regular clocks, quantum
  deltas, runs, and a dominant cadence with exceptions.
- Constant with no value payload; change events; the ordinary
  integer/scaled/XOR/raw codec; a decimal grid with exact IEEE corrections and a
  remembered scale hint.
- Residual modes: zero, sign bitmap, packed bitmap, fixed width, sparse gaps,
  varints with optional zstd.
- Inline up to 16 bytes; external payloads stored separately; an immutable
  allocation mask beside a separately mutable live mask.
- Compact exact summaries, gauge and counter distinguished, increase and reset
  summaries.
- Checksums, versions on the new formats, reads of old directories and migration
  of an old file. This is a new production parser, not a call into a `spike/`
  test helper.

### Maintenance

- The safe prefix follows the series' own time and its lateness bound.
- Encoding happens outside the writer; publication checks the version.
- Payloads, clock ownership, the directory, head removal and the frontier all
  move in one transaction.
- A bounded expiry pass, quiet-head cleanup, a partial live mask, last-owner
  clock deletion, and restoration of the due record when an empty series revives.
- Maintain is called explicitly by the application; there is no internal
  background scheduler yet.

## 4. What is not implemented, or not proven

| Work | Status |
|---|---|
| Packed mutable tail | absent; the head is exact separate rows |
| Merge or repack of small sealed groups | absent |
| Choosing closure by SQLite page cost | absent; there are count, span and clock-byte limits |
| Automatic retraining of the grid hint | absent |
| Aggregate and rate API | absent; summaries are written, raw is handed out |
| Several decode workers | absent; the encoder is separated from one decoder |
| Public series deletion | absent; an empty series stays in cardinality |
| Background scheduler | absent; Maintain is an explicit call |
| Records, KV, SQL, a network service | not started |
| Steady-state WAL, RSS, cold reads, p95/p99 | not measured for the engine |
| A full power-loss and crash matrix | not done |

Shared clock objects currently hold a group's whole time context. Sharing an
identical relative pattern across different absolute ranges is not introduced.
Eight clock descriptors are cached, and only within one query.

Raw bit-exactness does not automatically make a SQL SUM or AVG bit-exact: an
aggregation contract needs its own decision on rounding, NaN, infinities and the
order of addition. A stored sum does not replace that decision.

## 5. What was checked

Environment: Windows host, Ryzen 7 7700; Go 1.27.1; Linux Docker; modernc SQLite
1.59.0; klauspost/compress 1.19.0.

- Every ordinary test passed with a shuffled order on Windows.
- Every package passed `go test -race -shuffle=on ./...` on Linux.
- Lint, formatting, tidy of both main Go modules and govulncheck passed.
- The new binary readers survived a 15-second fuzz run, about 119450 executions,
  with no crash found. That is a bounded run, not an exhaustive proof.
- Golden vectors for directory v1 and v2 and for the clock; a schema-v1 file
  opened by the new implementation; bit-level extremes and residual round trips.
- An injected SQL error in publication rolls back the payload writes already
  done, the head removal, the allocation state and the group publication.
- A subprocess writes a head or a sealed group and exits without Close; another
  process opens the file and gets the previous values back. The exit happens
  after a completed commit, not inside every possible step of COMMIT.
- Races between Ingest, Maintain, retention and Read; a stale candidate; partial
  retention; clock ownership; the watermark edge; limits and cancellation.
- A full Alibaba and TSBS load through the public API, then Close, Open and a
  bit-level check of every returned sample rather than a chosen window.
- A CGO-free stripped linux/amd64 probe using the metrics API: 8175776 bytes,
  6668288 bytes above an empty baseline.

These were local checks of an uncommitted state. They are not a fresh CI run on
macOS, Windows and Linux, and they do not prove the absence of a race outside
the tested scenarios.

## 6. How the engine was checked against the corpora

`metrics/TestCorpusThroughPublicStore` uses the same normalised JSONL as the
earlier comparisons. It does not build finished payloads directly:

```text
parse one series
→ Ingest in chunks of 7681 points
→ Maintain after each chunk
→ Close
→ the size of the real file
→ Open
→ Read every series
→ compare every timestamp and IEEE float bit
```

Retention of 100 years keeps the historical timestamps; the head and batch
maxima are 8192; lateness is 0. The series in this comparison are registered as
gauges, as in the original storage harness; counter semantics are covered by
separate tests. The last sample, and any tail too short to pack, stay mutable.

Diagnostic time for input parsing, ingestion and maintenance was about 73
seconds on Alibaba and 41 seconds on TSBS; reopened parsing, reading and
validation about 3.1 and 2.5 seconds. Those are not clean ingest rates or query
latencies, and not a CPU comparison against other engines. The runs were not
performed as an isolated load test.

To reproduce, after preparing the JSONL with the existing bench runners:

```powershell
$env:TINYSTORE_JSONL = '<corpus-directory>/series.jsonl'
go test ./metrics -run '^TestCorpusThroughPublicStore$' -v -count=1
```

For numbers comparable with this report, run Go 1.27.1 in a Linux container with
the repository and the corpus mounted. An ordinary test run skips this corpus
test when the variable is unset.

## 7. What bit-exactness means for the others

- The TinyStore engine was checked on both full corpora in the new runs.
- VM returned every value bit-exactly in the earlier Alibaba run.
- VM changed 147751 of the 151200 float values checked in the earlier TSBS run,
  so its exactness cannot be carried from Alibaba to an arbitrary float workload.
- Prometheus was checked in full on TSBS; on Alibaba only over the stated
  two-hour window of 468470 samples across 1240 series. It should not be written
  that a full bit-level export was done for it on Alibaba.

## 8. The next priority

The first next stage is a packed durable head under the same Ingest, Read and
frontier contracts. TSBS already shows what the current one costs: 6.4 MB of a
12.8 MB file. After that, the registry and postings, and group compaction as
data arrives gradually.

An improvement is accepted on the whole file **together with WAL, RSS and
latencies**, keeping exact reopen, late input, version and CAS behaviour, and
retention. Force-sealing an unsafe head, or excluding it from the denominator or
from the file, is not allowed.

Only then is it worth updating a public scoreboard against freshly run VM and
Prometheus, with an explicit policy on caches, retention and an identical load
mode. The honest achievement today is a working, guarded first metrics slice and
the migration of the main algorithms out of the research tests — not a finished
architecture, and not a reproduced engine win over VM.
