# Combined storage prototype

Same pinned Alibaba and TSBS inputs as the previous rounds: 12431885 and
5090400 samples. Ryzen 7 7700, Docker linux/amd64, Go 1.27.1, SQLite driver
1.59.0, klauspost/compress 1.19.0. Group width 32, inline limit 16 value bytes.

## Result

| Corpus | Previous best file | Combined file | Combined B/sample |
|---|---:|---:|---:|
| Alibaba | 5402624 | **4485120** | **0.360776** |
| TSBS | 4919296 | 4939776 | 0.970410 |

Alibaba improves another 17.0%; compared with the original 9224192-byte
Alibaba file, the reduction is 51.4%. TSBS is 0.4% larger than the best
concatenated-body layout from the preceding round, so the combination is not
a universal density winner. Against the previous *separate-body* TSBS layout
(5152768 bytes), it is smaller.

The previous VM Alibaba complete directory was 6338675 bytes: this prototype
is 29.2% smaller under that full-directory accounting. VM data plus metadata
without caches were 3281990 bytes and remain smaller. VM was not rerun or
retuned. This is a bulk-file result, not a general engine or throughput win.

## What is connected

- An exact change-event mode records positions of value changes and either
  integer deltas, exact hundredths deltas, or literal IEEE bits. It competes
  against the existing encoded value stream. A constant block has no value
  body at all. This prototype uses varint gaps, not Rice.
- Value bodies of at most 16 bytes live inside the compressed metadata
  directory. Larger bodies retain separate SQLite rows and their own checksum.
- A shared clock object now owns each microblock's time head and clock stream.
  Value directories no longer repeat individual start/end/count fields.
  Clock objects, digest index, references and ownership counts are all charged.
- An immutable 32-bit allocation mask maps external payload ids through rank
  (`first_id + popcount(earlier allocation bits)`). A separate live mask tracks
  expiry. Removing a block never shifts later payload addresses.
- Summary fields use the first value or count times first only when their
  reconstruction is bit-identical. Other summaries retain their exact scalar
  or literal-bit representation, including floating sum rounding differences.
- A group checksum binds its series/key, clock reference, payload base id,
  allocation/live masks and compressed directory. Inline values and constant
  descriptors are protected by that checksum. The clock object has its own
  checksum. External bodies bind the original microblock head and clock bytes.
- Verification uses a separate decoder and an eight-entry FIFO clock cache.
  A cached entry holds at most 32 times 240 timestamps, roughly 60 KiB of
  timestamp elements; this is not a measured total-RSS bound.

The event selector and metadata scalar logic explicitly preserve negative zero
and NaN payload bits. A separate event-codec edge test covers signed zero,
NaN payloads, infinities, subnormals, integer steps and decimal steps. It is not
a full nonfinite-value SQLite aggregation or corruption-fuzzing suite.

## Verification and limits

Both corpora were fully read back from SQLite. Every original timestamp,
float bit and per-microblock summary was checked. The file is measured after
truncate checkpoint and before deletion; `page_count * page_size` equals
dbstat totals and freelist_count is zero.

A partial-expiry probe removes the first allocated block of the first group
(or its first inline block when none are allocated), keeps the allocation mask
unchanged, reseals the directory, updates the parent summary and verifies all
remaining blocks and the persisted parent summary. A whole-series deletion
then removes its remaining external payloads and decrements shared clocks in
one transaction. Reference counts, absence of dangling clocks and payload-row
counts are checked afterwards. This is not concurrent retention or crash testing.

Diagnostic build time was about 2.7 s for Alibaba and 2.8 s for TSBS; complete
warm readback plus checking took about 0.6 s and 0.2 s respectively in one
parallel run. Input parsing, SQL build and verification are separate phases.
These are not ingestion throughput, cold query latency, or a controlled CPU
comparison. Clock-cache hit counts include repeated validation accesses.

Encoder/decoder contention, a production decoder pool, single-pass ingestion,
WAL, restart recovery, cold queries and RSS remain unmeasured. The directory
parser is a checksummed prototype, not a hardened released format. No production
codec or dependency was changed in this round.

## Reproduce

```powershell
docker run --rm -m 6g -v <repo>:/src -v <corpus>:/corpus -v tinystore-gocache:/go -w /src -e TINYSTORE_JSONL=/corpus/series.jsonl -e GOCACHE=/go/build-cache golang:1.27 go test ./spike -run '^TestCombined' -v -count=1
```

Repeat with `tinystore-tsbs` for the second corpus. Code is in
`spike/combined_spike_test.go`. Both corpus runs, normal tests and spike lint
passed. Full `task check` was not run.
