# First real corpus: NAB

Ryzen 7 7700, Go 1.27.1 linux/amd64 in Docker, SQLite driver 1.59.0,
klauspost/compress 1.19.0. Base codec: `9e34181`.

Source: [NAB](https://github.com/numenta/NAB/tree/ea702d75cc2258d9d7dd35ca8e5e2539d71f3140/data),
revision `ea702d75cc2258d9d7dd35ca8e5e2539d71f3140`, MIT repository.
Selected the complete `realAWSCloudwatch` and `realKnownCause` directories:
17 + 7 real series, no generated samples. Per-file SHA256 hashes are in
`bench/nab-sha256.txt`; source descriptions are in NAB's data README.

137301 input rows become 137256 samples after stable timestamp sorting and
last-input-value selection at 45 duplicate timestamps. Both engines receive
that same normalized input. Original timestamps are retained, interpreted as
UTC. Corpus files stay in the system temporary directory, outside Git.

## Measured sizes

| Subset | Samples | Current payload B/sample | Best experimental payload | Current SQLite B/sample |
|---|---:|---:|---:|---:|
| AWS CloudWatch | 67718 | 2.7313 | 2.7288 | 3.8711 |
| Known cause | 69538 | 5.0541 | 4.8782 | 6.7739 |
| Both, one SQLite file | 137256 | — | — | 5.1030 |

Blocks contain at most 240 samples. Every current block and experimental
transform is reconstructed and checked bitwise. The candidates are byte
transpose plus zstd, and arbitrary-width packed differences of IEEE bit words.
They pay nine framing bytes and retain the current representation if larger.
They are size experiments, not supported on-disk formats. They run only on
blocks with a regular timestamp step; irregular blocks retain the baseline.
Decimal exceptions were not evaluated on this corpus.

The real opportunity is concentrated: ambient temperature goes from 6.6816 to
6.3751 payload B/sample; machine temperature from 6.6310 to 6.1905 (6.6%).
AWS barely changes. This narrows where a new residual encoding earns its cost.

SQLite includes every block, its existing gauge summaries, payloads, series
state, due index, a minimal label registry and its unique lookup index. Files
are newly built, inserted by series and measured after a truncate checkpoint.
This is a storage prototype, not a complete engine: no mutable head, general
label postings, ingest concurrency or retention workload is represented.

## VictoriaMetrics comparison and the exactness check

Single-node v1.152.0, image digest
`sha256:86ca5fdb6d87d56ba047b044039019ba2bd9042b36e35f6ea34e437b6c825cef`.
Flags: precisionBits=64, dedup.minScrapeInterval=0s, retentionPeriod=100y,
memory.allowedBytes=134217728. Long retention keeps the original 2013–2015
timestamps alive. No resampling or generated repetition of the corpus.

JSON import → force_flush → raw JSON export → request force_merge → graceful
shutdown. The merge request is asynchronous; this is not a certified final
compaction optimum. Export preserves all 137256 timestamps and counts, but
**13872 values do not round-trip bitwise** through this HTTP path. Example:
`0.20199999999999999` becomes `0.20200000000000001`.
This experiment does not isolate whether conversion happened during import,
internal storage or export. The diagnostic test reports mismatches rather than
asserting equality: a passing test is not a bit-exactness certification.

| Complete measured files | Logical bytes | B/sample |
|---|---:|---:|
| TinyStore SQLite prototype | 700416 | 5.1030 |
| VictoriaMetrics directory after shutdown | 596047 | 4.3426 |

VM breakdown: data 353465 B (including its on-disk indexing), cache 242574 B,
metadata 8 B. All files are counted, not only compressed sample streams.
These are logical lengths, not filesystem allocation units. The tiny corpus
and the scope difference make this a diagnostic comparison, not an engine
ranking. In particular, it does **not** establish a lossless victory for VM
under TinyStore's every-bit contract.

VM's [precision flag and export APIs](https://docs.victoriametrics.com/victoriametrics/single-server-victoriametrics/)
were checked against the running version. A configured precision of 64 alone
is insufficient evidence of an identical end-to-end float representation.

## Small optimization adopted

The encoder used to construct both timestamp streams before discovering that
the timestamps were regular and discarding both. It now checks the regular
case first. A successfully encoded integer block also skips decimal-scale
search, which would necessarily select scale zero and return no candidate.
The format and candidate output are unchanged.

Three 500 ms runs before/after, baseline supplied with Go's overlay mechanism:

| Encode one corpus block | Before | After |
|---|---:|---:|
| Allocations | 42 | 29 |
| Allocated bytes, approximate | 22514 | 20229 |
| Median time | 38.00 us | 37.22 us |

The clear win is 31% fewer allocations and about 10% fewer allocated bytes.
The timing change is small and is not claimed as a statistically established
speedup. All normal tests including golden payloads, corpus bitwise checks and
lint passed. Full `task check` and sustained ingest/query benchmarks were not run.

## Reproduce

```powershell
./bench/run-nab.ps1
./bench/run-nab.ps1 -Victoria
```

The second command binds localhost port 18428, uses a fresh VM storage
directory and stops its container afterwards. It preserves the corpus and
export for inspection. Existing downloads are hash-verified before reuse.
Benchmark encoding with `BenchmarkRealCorpusEncode` and set
`TINYSTORE_CORPUS` to the downloaded directory. Tests skip without that variable.
