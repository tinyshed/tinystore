# TinyStore 0.13.0

TinyStore 0.13.0 is not yet released. A table can now be kept as a copy of
another system's rows, hide its deleted rows and refuse an edit made from an
old version. A memo answers at once while it makes a new answer, a semaphore
lets a person's request pass background work and pauses when the service
behind it is down, and a queue gathers many events into one job that waits
for the morning. Search reads abbreviations and asks several indexes in one
call, a stream's query keeps to the rows of a statement and cuts sessions,
and metrics compare a window with the usual and write Prometheus' text.

- **SQL**
  - [What a statement answers](#what-a-statement-answers): `describe`, its columns without running it.
  - [A mirror of another system's rows](#a-mirror-of-another-systems-rows): `mirror`, `replace` and `upsert`, with what was added, changed and gone.
  - [Deleted rows and versions](#deleted-rows-and-versions): `deleted` and `version`, `ifVersion`, `restore` and `purge`.
- **KV**
  - [An answer kept while a new one is made](#an-answer-kept-while-a-new-one-is-made): `fresh`, `fetch` and `clear`.
- **Locks**
  - [Urgent and background holds](#urgent-and-background-holds): `background`, a hold's priority and its `timeout`.
  - [A pause when a service is down](#a-pause-when-a-service-is-down): `breaker`, `permit.healthy()` and `state`.
- **Jobs**
  - [Gather what arrives into one job](#gather-what-arrives-into-one-job): `gather`, with `settle` and `max`.
  - [Quiet hours](#quiet-hours): `quiet`, a queue's hours or a job's own.
- **Search**
  - [Cut a snippet](#cut-a-snippet): the piece of a field around its first match.
  - [Abbreviations and synonyms](#abbreviations-and-synonyms): `synonyms`, read both ways.
  - [Ask several indexes at once](#ask-several-indexes-at-once): `store.search`, its groups and `merged`.
- **Records**
  - [A where kept to a database's statement](#a-where-kept-to-a-databases-statement): `db.statement` in a `where`.
  - [Sessions](#sessions): a stream's events cut by a pause.
- **Metrics**
  - [Compare now with usual](#compare-now-with-usual): `compare`, a window against the windows before it.
  - [To Prometheus](#to-prometheus): the newest sample of every series as Prometheus' text, in Rust.
- **Command line**

  - [Times in one zone](#times-in-one-zone): `--tz` and `TINYSTORE_TZ`.

> [!WARNING]
> **Bun, Node and Python: a database's `describe` is now `label`**
> A database and its transaction had a text property `describe`, such as
> `'sql app'`, that names it in errors. `describe` is now the call that
> describes a statement's columns, and the text is `label`:
>
> ```diff
> - log.warn(`${db.describe}: sync skipped`)
> + log.warn(`${db.label}: sync skipped`)
> ```

## What a statement answers

`describe` gives the columns that a statement answers, in the statement's
order, without running it. A console, a dashboard or an export that shows a
statement someone else wrote can name its columns even when no row comes
back ([What a statement answers](../guides/sql/README.md#what-a-statement-answers)):

```ts
const columns = await db.describe`select id, title, length(title) as size from notes where author_id = ${userId}`
// [{ name: 'id', type: 'TEXT' }, { name: 'title', type: 'TEXT' }, { name: 'size' }]
```

```python
columns = await db.describe("select id, title, length(title) as size from notes where author_id = ?", user_id)
# [Column(name='id', type='TEXT'), Column(name='title', type='TEXT'), Column(name='size', type=None)]
```

```go
columns, err := sqldb.Describe(ctx, db, `select id, title, length(title) as size from notes where author_id = ?`, userID)
// [{Name:id Type:TEXT} {Name:title Type:TEXT} {Name:size Type:}]
```

```rust
let columns = db.describe(sql!("select id, title, length(title) as size from notes where author_id = ?", user_id))?;
// [Column { name: "id", declared: Some("TEXT") }, …, Column { name: "size", declared: None }]
```

- A table's own column carries the type its table declares. An expression
  has none.
- Nothing of the statement runs, so a statement given as text alone, without
  its values, is described too.
- A statement that writes is `invalid` (contract SQL-16).
- `tinystore sql` on the command line prints a query's columns, and `no rows`
  under them, when it finds no row.

## A mirror of another system's rows

A program that syncs a course's works from another system compared the list
with its table by hand, row by row. A mirror does it: give it the list the
source answered, and it writes only the difference in one commit and answers
what was added, changed and gone ([Mirrors](../guides/sql/mirror.md)):

```ts
const works = db.mirror<Work>('works', { key: ['course_id', 'id'], gone: 'gone_at', changeOn: ['grade'] })

const diff = await works.replace({ course_id: 1 }, fetched, { minKept: 0.5 })
for (const { before, after } of diff.changed) notify(after, before.grade, after.grade)
// diff: { added: Work[], changed: { before, after }[], gone: Work[], same: 41, suspect: false }
await works.upsert(changedSinceYesterday) // a delta: adds and changes, marks nothing gone
```

```python
works = db.mirror("works", Work, key=["course_id", "id"], gone="gone_at", change_on=["grade"])

diff = await works.replace({"course_id": 1}, fetched, min_kept=0.5)
for changed in diff.changed:
    notify(changed.after, changed.before.grade, changed.after.grade)
await works.upsert(changed_since_yesterday)
```

```go
works := sqldb.OpenMirror[Work](db, "works", sqldb.MirrorOptions{
	Key: []string{"course_id", "id"}, Gone: "gone_at", ChangeOn: []string{"grade"},
})

diff, err := works.Replace(ctx, map[string]any{"course_id": 1}, fetched, sqldb.MinKept(0.5))
for _, changed := range diff.Changed {
	notify(changed.After, changed.Before.Grade, changed.After.Grade)
}
diff, err = works.Upsert(ctx, changedSinceYesterday)
```

```rust
let works = db.mirror::<Work>("works").key(["course_id", "id"]).gone("gone_at").change_on(["grade"]).open()?;

let diff = works.min_kept(0.5).replace(&[("course_id", 1)], &fetched)?;
for changed in &diff.changed {
    notify(&changed.after, changed.before.grade, changed.after.grade);
}
works.upsert(&changed_since_yesterday)?;
```

- `replace(scope, rows)` makes the rows of the scope, here course 1, what the
  list lists. A row the list gives as it is held is not written at all
  (contracts SQL-17, SQL-18 and SQL-19).
- With `gone`, a row the list leaves out is marked with the time instead of
  deleted. `changeOn / change_on / ChangeOn / change_on` names the columns
  whose change makes a row `changed`.
- `minKept / min_kept / MinKept / min_kept` guards against a source that
  answers an empty page during an outage. If the list would leave fewer than
  that fraction of the scope's rows, nothing is written, and the answer has
  `suspect: true` (contract SQL-20).
- In Rust a mirror joins its database's transaction, `tx.with(&works)`. The
  SDKs have no mirror inside a transaction yet.
- A kept state of a sync per scope, a cursor that the next call resumes
  from, is not built.

On 5,000 rows of which 1 % changed, a `replace` wrote 50 rows in 9.2 ms. A
delete of every row and an insert of the list wrote 5,000 in 15.0 ms, and an
upsert of the list 5,000 in 17.6 ms. These are the medians of nine passes in
one run, a release build on a 4 vCPU Intel Xeon 2.10 GHz Linux container
with 15 GiB, while other builds shared the CPU:

```sh
cargo test --release -p tinystore --lib --features async,testing mirror_against_the_loops -- --ignored --nocapture
```

## Deleted rows and versions

A table's handle can now keep two columns for you. With `deleted`, a delete
marks the row instead of removing it, and every call of the handle skips
marked rows. With `version`, an edit made from an old version fails with a
conflict instead of replacing someone else's work
([Deleted rows and versions](../guides/sql/deleted-and-versions.md)):

```ts
const tasks = db.table<Task>('tasks', { deleted: 'deleted_at', version: 'version' })

const seen = await tasks.where({ id: 1 }).one() // { id: 1, title: 'Draft', deleted_at: null, version: 0 }
await tasks.where({ id: 1 }).update({ title: 'from Ann' }, { ifVersion: seen!.version }) // version 1
await tasks.where({ id: 1 }).update({ title: 'from Ben' }, { ifVersion: seen!.version })
// ConflictError: sql app: table tasks: the row is at version 1, not 0

await tasks.where({ id: 1 }).delete() // sets deleted_at, and the row stays in the file
await tasks.where({ id: 1 }).restore() // clears deleted_at: the row is back
await tasks.deletedOnly().where('deleted_at < ?', monthAgo).purge() // deletes for good
```

```python
tasks = db.table("tasks", Task, deleted="deleted_at", version="version")

seen = await tasks.where(id=1).one()  # Task(id=1, title='Draft', deleted_at=None, version=0)
await tasks.where(id=1).update({"title": "from Ann"}, if_version=seen.version)  # version 1
await tasks.where(id=1).update({"title": "from Ben"}, if_version=seen.version)
# tinystore.ConflictError: sql app: table tasks: the row is at version 1, not 0

await tasks.where(id=1).delete()  # sets deleted_at, and the row stays in the file
await tasks.where(id=1).restore()  # clears deleted_at: the row is back
await tasks.deleted_only().where("deleted_at < ?", month_ago).purge()  # deletes for good
```

```go
tasks := sqldb.OpenTable[Task](db, "tasks", sqldb.Deleted("deleted_at"), sqldb.Version("version"))

seen, _, err := tasks.Where(sqldb.Eq{"id": 1}).One(ctx) // {ID:1 Title:Draft DeletedAt:<nil> Version:0}
_, err = tasks.Where(sqldb.Eq{"id": 1}).Update(ctx, sqldb.Set{"title": "from Ann"}, sqldb.IfVersion(seen.Version))
_, err = tasks.Where(sqldb.Eq{"id": 1}).Update(ctx, sqldb.Set{"title": "from Ben"}, sqldb.IfVersion(seen.Version))
if errors.Is(err, tinystore.ErrConflict) {
	// sql app: table tasks: the row is at version 1, not 0
}

_, err = tasks.Where(sqldb.Eq{"id": 1}).Delete(ctx)  // sets deleted_at, and the row stays in the file
_, err = tasks.Where(sqldb.Eq{"id": 1}).Restore(ctx) // clears deleted_at: the row is back
_, err = tasks.DeletedOnly().Where(sqldb.SQL("deleted_at < ?", monthAgo)).Purge(ctx) // deletes for good
```

```rust
let tasks = db.table::<Task>("tasks").deleted("deleted_at").version("version");

let seen = tasks.filter(sql::eq("id", &1)).one()?.unwrap(); // Task { id: 1, title: "Draft", deleted_at: None, version: 0 }
tasks.filter(sql::eq("id", &1)).if_version(seen.version).update([("title", sql::value("from Ann"))])?; // version 1
let ben = tasks.filter(sql::eq("id", &1)).if_version(seen.version).update([("title", sql::value("from Ben"))]);
if ben.is_err_and(|error| error.kind() == ErrorKind::Conflict) {
    // sql app: table tasks: the row is at version 1, not 0: conflict
}

tasks.filter(sql::eq("id", &1)).delete()?; // sets deleted_at, and the row stays in the file
tasks.filter(sql::eq("id", &1)).restore()?; // clears deleted_at: the row is back
tasks.deleted_only().filter(sql!("deleted_at < ?", month_ago)).purge()?; // deletes for good
```

- The table keeps the columns, made by your migration. A table opened
  without the options writes exactly the statements it wrote before.
- A marked row is not shown, counted or changed unless you ask with
  `withDeleted()` or `deletedOnly()` (contract SQL-21). A `purge` on the
  plain handle is `invalid`, so that it never removes live rows (contract
  SQL-22).
- One statement decides `ifVersion`, so an edit of several rows writes all of
  them or none (contracts SQL-23 and SQL-24).
- A statement you write by hand, `db.all('select …')`, sees every row.

## An answer kept while a new one is made

A memo with only `keep` made every caller wait for the whole build again
once `keep` ended, and had nothing to answer when the build failed. With
`fresh`, an older answer is answered at once while one new answer is made in
the background, and a build that fails leaves the last good answer in place
([Once](../guides/kv/once.md#an-answer-kept-while-a-new-one-is-made)):

```ts
const books = store.once<GradeBook>('cabinet-books', { fresh: '10m', keep: '12h' })

const { value, age, stale } = await books.fetch(String(userId), () => cabinet.book(userId))
await books.under(courseId).clear() // a branch and every branch under it, in one commit
```

```python
books = store.once("cabinet-books", GradeBook, fresh="10m", keep="12h")

answer = await books.fetch(str(user_id), lambda: cabinet.book(user_id))  # answer.value, .age, .stale
await books.under(course_id).clear()
```

```go
books, err := kv.OpenOnce[GradeBook](store, "cabinet-books", kv.Fresh(10*time.Minute), kv.Keep(12*time.Hour))

answer, err := books.Fetch(ctx, userID, func(ctx context.Context) (GradeBook, error) { return cabinet.Book(ctx, userID) })
// answer.Value, answer.Age, answer.Stale
err = books.Under(courseID).Clear(ctx)
```

```rust
let books = store.once::<GradeBook>("cabinet-books").fresh(Duration::from_mins(10)).keep(Duration::from_hours(12)).open()?;

let cabinet = cabinet.clone(); // the build may outlive the call, so it owns what it uses
let answer = books.fetch(user_id, move || cabinet.book(user_id))?; // answer.value, answer.age, answer.stale
books.under(course_id).clear()?;
```

- One build of a key runs in the background at a time, across every client
  of the store (contract KV-16). A failed build holds off the next one for a
  tenth of `fresh`, between a second and a minute (contract KV-17).
- `fetch` answers the value with its `age` and whether it is `stale`
  (contract KV-18). `run` answers the value alone, as before.
- `clear` forgets every answer of a branch and of the branches under it in
  one commit (contract KV-19).
- In Rust with async, a handle opened with `fresh` takes `spawn`, the
  runtime that the background build runs on.
- Waiting a bounded time for the new answer before taking the stale one is
  not built.

## Urgent and background holds

Every request to an outside service goes through one semaphore, and
background jobs should not fill its line while a person waits. A semaphore
now keeps places for urgent holds, and a hold's `timeout` counts from the
moment it gets its place
([Semaphores](../guides/locks/semaphores.md#urgent-and-background)):

```ts
const cabinet = store.semaphore('cabinet', { limit: 8, background: 4 })

await cabinet.hold('requests', permit => syncGrades(permit.signal), {
	priority: 'background',
	wait: '60s',
	timeout: '15s',
})
await cabinet.hold('requests', permit => fetchProfile(user.id, permit.signal)) // urgent: passes the background line
```

```python
cabinet = store.semaphore("cabinet", limit=8, background=4)

async with cabinet.hold("requests", priority="background", wait="60s", timeout="15s"):
    await sync_grades()
async with cabinet.hold("requests"):  # urgent: passes the background line
    await fetch_profile(user.id)
```

```go
cabinet, err := locks.OpenSemaphore(store, "cabinet", locks.Limit(8), locks.Background(4))

err = cabinet.Hold(ctx, "requests", syncGrades,
	locks.InBackground(), locks.Wait(time.Minute), locks.Timeout(15*time.Second))
err = cabinet.Hold(ctx, "requests", fetchProfile) // urgent: passes the background line
```

```rust
let cabinet = store.semaphore("cabinet").limit(8).background(4).open()?;

cabinet
    .key("requests")
    .background()
    .wait(Duration::from_secs(60))
    .timeout(Duration::from_secs(15))
    .hold(|_| sync_grades())?;
cabinet.hold("requests", |_| fetch_profile(&user.id))?; // urgent: passes the background line
```

- A hold is urgent unless you ask for the background, so every hold written
  before this release is urgent.
- `background` is how many of a key's places background holds can take at
  once. With 8 places and `background: 4`, urgent holds always find 4
  places. Within each priority, holds are served in the order they came
  (contracts LOCK-09 and LOCK-10).
- Past its `timeout`, a hold loses its place and fails as at `maxHold`, with
  a lost error, and its signal aborts (contract LOCK-11).

## A pause when a service is down

When the service behind a semaphore is down, every caller waited for its own
timeout. A breaker puts the key down for a pause after a number of failed
holds in a row, and every caller hears it at once
([Semaphores](../guides/locks/semaphores.md#a-pause-when-what-it-guards-is-down)):

```ts
const cabinet = store.semaphore('cabinet', { limit: 8, breaker: { failures: 2, pause: '30s' } })

try {
	return await cabinet.hold('requests', async permit => {
		const response = await fetch(url, { signal: permit.signal })
		if (response.status === 404) {
			permit.healthy() // the cabinet answered: it is up
			throw new NotFound(user.id)
		}
		return response.json()
	})
} catch (err) {
	if (err instanceof UnavailableError) return showCached(user.id) // the cabinet is down
	throw err
}
const { up, downSince, waiting, holding } = await cabinet.state('requests')
```

```python
cabinet = store.semaphore("cabinet", limit=8, breaker=Breaker(failures=2, pause="30s"))

try:
    async with cabinet.hold("requests") as permit:
        response = await client.get(url)
        if response.status_code == 404:
            permit.healthy()  # the cabinet answered: it is up
            raise NotFound(user.id)
except UnavailableError:
    return show_cached(user.id)  # the cabinet is down
state = await cabinet.state("requests")  # state.up, state.down_since, state.waiting, state.holding
```

```go
cabinet, err := locks.OpenSemaphore(store, "cabinet", locks.Limit(8), locks.Breaker(2, 30*time.Second))

err = cabinet.Hold(ctx, "requests", func(ctx context.Context, permit *locks.Lease) error {
	response, err := get(ctx, url)
	if err == nil && response.StatusCode == http.StatusNotFound {
		permit.Healthy() // the cabinet answered: it is up
		return errNotFound
	}
	return err
})
if errors.Is(err, tinystore.ErrUnavailable) {
	return showCached(user.ID) // the cabinet is down
}
state, err := cabinet.State(ctx, "requests") // state.Up, state.DownSince, state.Waiting, state.Holding
```

```rust
let cabinet = store.semaphore("cabinet").limit(8).breaker(2, Duration::from_secs(30)).open()?;

let fetched = cabinet.hold("requests", |permit| {
    let response = get(&url)?;
    if response.status() == 404 {
        permit.healthy(); // the cabinet answered: it is up
        return Err(not_found(&user.id));
    }
    Ok(response)
});
if fetched.as_ref().is_err_and(|error| error.kind() == ErrorKind::Unavailable) {
    show_cached(&user.id); // the cabinet is down
}
let state = cabinet.state("requests")?; // state.up, state.down_since, state.waiting, state.holding
```

- A hold fails when its function throws or returns an error, or runs past
  its `timeout` or `maxHold`. A hold that succeeds resets the count.
- While the key is down, every hold of it fails at once with an unavailable
  error: `UnavailableError` in Bun and Python, `ErrUnavailable` in Go and
  `ErrorKind::Unavailable` in Rust (contract LOCK-12). After the pause, one
  hold goes through, and its result puts the key up or down again (contract
  LOCK-13).
- `healthy()` says the service answered, so the hold counts as no failure
  even if the function then throws.
- `state` says whether the key is up, since when it is down, its last
  failure, and how many holds wait and hold a place (contract LOCK-14).
- The breaker lives in the memory of the process that holds the store. A
  restart starts every key up (NOT-14).

100,000 uncontended pairs of a hold and its release took 1.515 µs per pair
on a plain semaphore and 1.552 µs on one with `background` and a breaker.
These are the medians of seven passes in turns in one run, a release build
on a 4 vCPU Intel Xeon 2.10 GHz Linux container with 15 GiB, while other
builds shared the CPU:

```sh
cargo test --release -p tinystore --lib --features testing hold_and_release_with_and_without -- --ignored --nocapture
```

## Gather what arrives into one job

Grades appear one by one, and a student should get one push for all of
them. `gather` collects what arrives under one id into one job, which runs
`settle` after the last gather, and no later than `max` after the first
([Gather and quiet hours](../guides/jobs/gather.md)):

```ts
const batch = store.queue<Notice[]>('notify-batch')

await batch.gather('grades:7', [{ course: 1, grade: 'A' }], { settle: '5m', max: '1h' }) // { added: true, count: 1, at }
await batch.gather('grades:7', [{ course: 2, grade: 'B' }], { settle: '5m', max: '1h' }) // { added: false, count: 2, at }

batch.work(async notices => push(7, `${notices.length} new grades`)) // one push with both
```

```python
batch = store.queue("notify-batch", list[Notice])

await batch.gather("grades:7", [Notice(course=1, grade="A")], settle="5m", max="1h")  # Gathered(added=True, count=1, at=…)
await batch.gather("grades:7", [Notice(course=2, grade="B")], settle="5m", max="1h")  # Gathered(added=False, count=2, at=…)


async def notify(notices: list[Notice], run: tinystore.Run) -> None:
    await push(7, f"{len(notices)} new grades")  # one push with both


worker = batch.work(notify)
```

```go
batch, err := jobs.OpenQueue[[]Notice](store, "notify-batch")

every := jobs.Settle(5 * time.Minute).Max(time.Hour)
gathered, err := batch.Gather(ctx, "grades:7", []Notice{{Course: 1, Grade: "A"}}, every) // {Added: true, Count: 1, At: …}
gathered, err = batch.Gather(ctx, "grades:7", []Notice{{Course: 2, Grade: "B"}}, every)  // {Added: false, Count: 2, At: …}

err = batch.Work(ctx, func(ctx context.Context, notices []Notice, run *jobs.Run) error {
	return push(ctx, 7, fmt.Sprintf("%d new grades", len(notices))) // one push with both
})
```

```rust
use tinystore::jobs::Gather;

let batch = store.queue::<Vec<Notice>>("notify-batch").open()?;
let every = Gather::settle(Duration::from_mins(5)).max(Duration::from_hours(1));
let gathered = batch.gather("grades:7", &vec![Notice { course: 1, grade: "A".into() }], every)?; // added, count 1
let gathered = batch.gather("grades:7", &vec![Notice { course: 2, grade: "B".into() }], every)?; // count 2

let worker = batch.work(|notices: Vec<Notice>, _run| push(7, &format!("{} new grades", notices.len())))?;
```

- The items stay in the order they arrived. A gather while the job runs adds
  its items for the next run, and none is lost when a run fails (contracts
  JOB-22 and JOB-23).
- The value is a list. A job under the id that repeats, or a gather that
  gives `at`, `delay`, `every` or `cron`, is `invalid`.
- In Rust and in Bun, `tx.with(batch).gather(…)` gathers with a database's
  transaction. Python's database transaction, the store's transaction in
  the SDKs and Go's transactions have no gather.
- A copy of a store on another node refuses a gather: gather at the store's
  home.

## Quiet hours

Nothing should be sent from 23:00 to 07:00 Moscow time. A queue's quiet
hours move every time the store gives a job inside them to their end
([Quiet hours](../guides/jobs/gather.md#quiet-hours)):

```ts
const night = { from: '23:00', to: '07:00', timeZone: 'Europe/Moscow' }
const pushes = store.queue<Notice[]>('notify-push', { quiet: night })

await pushes.gather('grades:7', [{ course: 1, grade: 'A' }], { settle: '5m' }) // at 23:58: { at: 07:00 the next morning }
await pushes.add([{ course: 0, grade: 'exam moved' }], { quiet: false }) // this job is not held
```

```python
night = tinystore.Quiet(from_="23:00", to="07:00", time_zone="Europe/Moscow")
pushes = store.queue("notify-push", list[Notice], quiet=night)

await pushes.gather("grades:7", [Notice(course=1, grade="A")], settle="5m")  # at 23:58: at 07:00 the next morning
await pushes.add([Notice(course=0, grade="exam moved")], quiet=False)  # this job is not held
```

```go
night := jobs.Quiet("23:00", "07:00", "Europe/Moscow")
pushes, err := jobs.OpenQueue[[]Notice](store, "notify-push", night)

gathered, err := pushes.Gather(ctx, "grades:7", []Notice{{Course: 1, Grade: "A"}}, jobs.Settle(5*time.Minute)) // at 23:58: At 07:00
added, err := pushes.Add(ctx, []Notice{{Course: 0, Grade: "exam moved"}}, jobs.NoQuiet()) // this job is not held
```

```rust
use tinystore::jobs::{Gather, Quiet};

let night = Quiet::hours("23:00", "07:00", "Europe/Moscow");
let pushes = store.queue::<Vec<Notice>>("notify-push").quiet(night).open()?;

let gathered = pushes.gather("grades:7", &vec![Notice { course: 1, grade: "A".into() }], Gather::settle(Duration::from_mins(5)))?;
let added = pushes.id("exam:3").quiet(Quiet::none()).add(&vec![Notice { course: 0, grade: "exam moved".into() }])?;
```

- The hours move an `add`'s time, a gather's settle, a retry's backoff and a
  repeat's next time, and an explicit `at` too (contract JOB-24). `get` and
  the command line show the moved time.
- A `from` after `to` wraps midnight. The hours follow the wall clock of
  their zone.
- A job's own `quiet` wins over its queue's. Quiet hours also win over a
  gather's `max`.

## Cut a snippet

A page's body is too long to show whole under its title. With `snippet`,
each hit carries the piece of one field around its first match, and the
matches inside that piece
([Show what matched](../guides/search/matches.md#cut-a-snippet)):

```ts
const found = await pages.search({ text: 'algebra', snippet: { field: 'plain', around: 60 } })
found.hits[0].snippet // { text: '…Then linear algebra took three weeks of…', marks: [{ start: 13, end: 20 }] }
```

```python
result = await pages.search("algebra", snippet={"field": "plain", "around": 60})
result.hits[0].snippet  # Snippet(text='…Then linear algebra took three weeks of…', marks=[Mark(start=13, end=20)])
```

```go
result, err := pages.Search(ctx, "algebra", search.Snippet("plain", 60))
result.Hits[0].Snippet // &{Text: "…Then linear algebra took three weeks of…", Marks: [{Start: 15, End: 22}]}
```

```rust
let found = pages.search("algebra").snippet("plain", 60).run()?;
let snippet = found.hits[0].snippet.as_ref().unwrap();
&snippet.text[snippet.marks[0].clone()] // "algebra"
```

`around` is how many characters to keep on each side, 80 unless given, and
the piece never cuts a word or a character in two. `marks` count as
`matches` do in each language. The store inserts no markup and escapes
nothing, so escape each piece yourself before it goes into HTML.

## Abbreviations and synonyms

Students type «кмзи» for a course named «Криптографические методы защиты
информации». An index's `synonyms` pair each short form with the phrase it
stands for, and Search reads the pair both ways
([Abbreviations and synonyms](../guides/search/synonyms.md)):

```ts
const catalog = store.index<{ name: string }>('catalog', {
	fields: { name: 4 },
	synonyms: { кмзи: 'криптографические методы защиты информации', ml: 'machine learning' },
})
const { hits } = await catalog.search('кмзи') // the course by its phrase, and «Экзамен по КМЗИ» by the word itself
```

```python
catalog = store.index(
    "catalog",
    Course,
    fields={"name": 4},
    synonyms={"кмзи": "криптографические методы защиты информации", "ml": "machine learning"},
)
result = await catalog.search("кмзи")
```

```go
catalog, err := search.OpenIndex[Course](store, "catalog", search.Fields{"name": 4},
	search.Synonyms{"кмзи": "криптографические методы защиты информации", "ml": "machine learning"})
result, err := catalog.Search(ctx, "кмзи")
```

```rust
let catalog = store
    .index::<Course>("catalog")
    .field("name", 4.0)
    .synonyms([("кмзи", "криптографические методы защиты информации"), ("ml", "machine learning")])
    .open()?;
let found = catalog.search("кмзи").run()?;
```

- The short form finds the phrase, its words next to each other and in
  order, by the same stems the index reads. The phrase's words find the
  short form. `matches` and snippets mark the text that is there (contract
  SRCH-23).
- Synonyms are read when a document is set, so a search pays nothing for
  them. Other synonyms in a later open are a change of settings, read again
  beside the index as a field added is.
- An index holds 1,000 synonyms at most, each a short form of one word and a
  phrase of 1 to 8 words.

Setting 20,000 documents of 50 words took 869 ms without synonyms and 903 ms
with 200. A search of two words took 116 µs and 100 µs, which is noise.
These are the medians of three passes, a release build on a 4 vCPU Intel
Xeon 2.10 GHz Linux container with 15 GiB, while other builds shared the
CPU:

```sh
cargo test --release -p tinystore --lib --features testing indexing_with_synonyms_takes -- --ignored --nocapture
```

## Ask several indexes at once

A "find anything" box asks one question of courses, pages and people.
`store.search` asks every index in one call, each with its own filter,
limit and snippet. It answers a group of hits for each index, and `merged`,
one list of the best of all of them by rank
([Ask several indexes at once](../guides/search/many.md)):

```ts
const found = await store.search({
	text: 'algebra',
	in: [
		{ index: courses, boost: 2, limit: 5 },
		{ index: pages, where: { space_id: 7 }, limit: 5, snippet: { field: 'plain', around: 60 } },
		{ index: people, limit: 5 },
	],
})
found.groups // [{ index: 'courses', hits, more: true }, { index: 'pages', hits, more: false }, …]
found.merged // [{ index: 'courses', group: 0, hit }, { index: 'pages', group: 1, hit }, …]
```

```python
found = await store.search(
    "algebra",
    among=[
        search.Among(courses, boost=2, limit=5),
        search.Among(pages, where={"space_id": 7}, limit=5, snippet={"field": "plain", "around": 60}),
        search.Among(people, limit=5),
    ],
)
found.groups  # [ManyGroup(index='courses', hits=[…], more=True, …), …]
found.merged  # [Merged(index='courses', group=0, hit=Hit(…)), …]
```

```go
found, err := search.Many(ctx, store, "algebra",
	search.Among(courses, search.Boost(2), search.Limit(5)),
	search.Among(pages, search.Where{"space_id": 7}, search.Limit(5), search.Snippet("plain", 60)),
	search.Among(people, search.Limit(5)))
found.Groups // [{Index: "courses", Hits: […], More: true}, …]
found.Merged // [{Index: "courses", Group: 0, Hit: &found.Groups[0].Hits[0]}, …]
```

```rust
use tinystore::search::eq;

let found = store
    .search("algebra")
    .among(&courses, |a| a.boost(2.0).limit(5))
    .among(&pages, |a| a.filter(eq("space_id", &7)).limit(5).snippet("plain", 60))
    .among(&people, |a| a.limit(5))
    .run()?;
found.groups[0].more // true: courses has more than five
found.merged[0].hit.id // the best of all three, by rank
```

- A call asks 1 to 32 indexes, a table's index among them. `more` says
  exactly whether an index has hits past its group's limit.
- An index that fails does not fail the others: its group carries the
  error.
- `merged` never compares scores of different indexes. It merges by
  reciprocal rank fusion, and `boost` weighs a group's ranks.
- The store's own indexes are searched in one snapshot of search.db.

In process, one search of 13 indexes of 200 documents each took 410 to
443 µs, against 391 to 414 µs for 13 single searches: about 6 % slower. The
gain is over a connection, one round trip instead of 13, and it is not
measured. These are medians of passes in turns in one run, a release build on
a 4 vCPU Intel Xeon 2.10 GHz Linux container with 15 GiB:

```sh
cargo test --release -p tinystore --lib --features testing many_against_single -- --ignored --nocapture
```

## A where kept to a database's statement

What do teachers use? A stream's query now keeps to the values of a
database's statement, so the store counts the teachers' events instead of
the program gathering everybody's and filtering them
([Reading](../guides/records/reading.md#a-where-kept-to-a-databases-statement)):

```ts
const teachers = db.statement`select id from teachers` // bound to its database; nothing runs yet
await events.count({ since: '1d', where: { userId: teachers } })
await events.list({ since: '1d', where: { userId: { not: teachers } } })
```

```python
teachers = db.statement("select id from teachers")  # bound to its database; nothing runs yet
await events.count(since="1d", where={"userId": teachers})
await events.list(since="1d", where={"userId": {"not": teachers}})
```

```go
teachers := db.Statement("select id from teachers") // bound to its database; nothing runs yet
events.Count(ctx, records.Query{Since: 24 * time.Hour, Where: records.Where{"userId": teachers}})
events.List(ctx, records.Query{Since: 24 * time.Hour, Where: records.Where{"userId": records.Not(teachers)}})
```

```rust
let (teachers, day) = (db.statement("select id from teachers"), Duration::from_hours(24)); // nothing runs yet
events.list().since(day).filter("userId", &teachers).count()?;
events.list().since(day).filter("userId", Not(&teachers)).page()?;
```

- The statement runs once, as the query starts, and its one column's values
  match as a list's do. It gives 100,000 rows at most.
- It is not read in one moment with the events, because they live in two
  files.
- `count`, `list`, `top`, `largest`, `aggregate` and `delete` take one. A
  tail refuses it.

Over 1,000,000 events of 100,000 people, a count kept to a statement of
50,000 ids took 1,039 ms. Walking every event and keeping the same ids in
the program took 13,579 ms. A count with no `where` took 2,304 ms, slower
than the count kept to the statement, and this pair is not explained yet.
These are the medians of seven passes in turns, a release build on a 4 vCPU
Intel Xeon 2.10 GHz Linux container with 15 GiB, while other builds shared
the CPU:

```sh
cargo test --release -p tinystore --lib --features testing records::condition::tests::a_count_kept -- --ignored --nocapture
```

## Sessions

What did a newcomer do in their first visit? `sessions` cuts a stream's
events into sessions by a pause: the events of one person, each within
`gap` of the one before
([Reading](../guides/records/reading.md#sessions)):

```ts
const visits = await events.sessions({
	since: '30d', by: 'userId', gap: '30m', max: '4h', firstSessions: 1, maxEvents: 50,
	where: { userId: db.statement`select id from students where first_seen_at > ${from}` },
}) // Session[]: [{ by: { userId: 1 }, from, to, count: 2, events: [{ at, name, fields… }, …], partial }]
```

```python
visits = await events.sessions(
    since="30d", by="userId", gap="30m", max="4h", first_sessions=1, max_events=50,
    where={"userId": db.statement("select id from students where first_seen_at > ?", start)},
)  # list[Session]
```

```go
newcomers := db.Statement("select id from students where first_seen_at > ?", from)
visits, err := events.Sessions(ctx, records.Query{Since: 30 * 24 * time.Hour, By: []string{"userId"},
	Gap: 30 * time.Minute, Max: 4 * time.Hour, FirstSessions: 1, MaxEvents: 50, Where: records.Where{"userId": newcomers}})
```

```rust
use tinystore::records::Sessions;

let (minute, day) = (Duration::from_mins(1), Duration::from_hours(24));
let newcomers = db.statement(tinystore::sql!("select id from students where first_seen_at > ?", from));
let visit = Sessions::by(["userId"]).gap(minute * 30).max(minute * 240).first_sessions(1).max_events(50);
let visits = events.list().since(day * 30).filter("userId", &newcomers).sessions(&visit)?; // Vec<Session>
```

- `max` ends a session that long after its first event. `firstSessions /
  first_sessions / FirstSessions / first_sessions` keeps each person's first
  sessions, and `maxEvents / max_events / MaxEvents / max_events` how many
  of each session's events come back.
- A session that the range cuts comes back with `partial`.
- The answer comes whole, 10,000 sessions and 64 MiB at most. Past either it
  is `limit`, never fewer sessions. Sessions are not paged yet: a shorter
  range, `firstSessions` or a `where` keeps the answer within the bounds.

Over 1,000,000 events of 8,000 people, five visits each, counting the range
took 1,380 ms, each person's first visit 1,724 ms, and the first visit with
its first 5 events 1,868 ms. These are the medians of seven passes in turns,
a release build on a 4 vCPU Intel Xeon 2.10 GHz Linux container with 15 GiB,
while other builds shared the CPU:

```sh
cargo test --release -p tinystore --lib --features testing records::sessions::tests::a_million -- --ignored --nocapture
```

## Compare now with usual

Is a call slower than usual? `compare` answers the `op` over the newest
window against the median of the same `op` over the windows before it, in
one call that reads one snapshot. The program keeps no baseline of its own
([Compare now with usual](../guides/metrics/compare.md)):

```ts
const now = await store.metrics.compare({
	name: 'moodle_call_ms',
	where: { source: 'server' },
	op: 'p50',
	window: '15m',
	against: { last: '7d', sameHour: true },
})
// { value: 840, usual: 310, ratio: 2.7, samples: 412, windows: 7 }
```

```python
now = await store.metrics.compare(
    "moodle_call_ms", op="p50", window="15m", where={"source": "server"}, against="7d", same_hour=True
)
# Compared(value=840.0, usual=310.0, ratio=2.7, samples=412, windows=7)
```

```go
now, err := metrics.Compare(ctx, store, metrics.Comparison{
	Name: "moodle_call_ms", Where: metrics.Where{"source": "server"}, Op: metrics.Percentile(50),
	Window: 15 * time.Minute, Against: 7 * 24 * time.Hour, SameHour: true,
})
// now.Value, now.Usual and now.Ratio are *float64: nil when there is none
```

```rust
let now = store
    .metrics()?
    .query()
    .name("moodle_call_ms")
    .filter("source", "server")
    .compare(Op::Percentile(50.0), Duration::from_mins(15))
    .against(Duration::from_hours(7 * 24))
    .same_hour()
    .run()?;
// Compared { value: Some(840.0), usual: Some(310.0), ratio: Some(2.7), samples: 412, windows: 7 }
```

- With `sameHour`, the windows before are the same quarter hour of each of
  the 7 days. Without it, they are every window of the week, 1,000 at most.
- A window without a sample counts in no median, never as zero.
- A timer's percentile is compared only with `estimate`.
- The store does not evaluate alert rules or notify anyone by itself yet.
  The guide shows a schedule that compares every minute and adds a job to
  the program's own queue.

On 10 gauges of a sample every 10 seconds for 7 days, one `compare` took
1.394 ms and 1.365 ms in two runs. The program's old way, one aggregate of
the week by 15 minutes and one of the newest window, took 20.98 ms and
21.75 ms. These are the medians of seven passes in turns, a release build
on a 4 vCPU Intel Xeon 2.10 GHz Linux container with 15 GiB:

```sh
cargo test -p tinystore --lib --release --features async,testing compare_against -- --ignored --nocapture
```

## To Prometheus

An existing Prometheus or Grafana can now see what the store keeps. The
Metrics engine writes the newest sample of every series as Prometheus' text
format, and your program's own HTTP server answers the scrape with it
([To Prometheus](../guides/metrics/exposition.md)):

```rust
let stats = store.metrics()?;
let mut body = Vec::new();
let written = stats.exposition().only_prefix("shop_").write(&mut body)?; // Written { names, series }
```

```text
# HELP shop_orders_total Orders placed.
# TYPE shop_orders_total counter
shop_orders_total{shop="msk"} 1027 1732622400000
```

- The call is in Rust alone. It is not over the wire yet, so Bun, Node,
  Python and Go have no call for it. From them, and from a shell,
  `tinystore metrics export` writes the same text.
- TinyStore serves no HTTP and has no listener for a scrape: the program's
  own server serves the bytes.
- `since` leaves out a series whose newest sample is older. Without it,
  every series the store keeps is written, with the time of its last sample.
- The store's own ingest reads the text back to the same names, labels,
  kinds and newest samples (MET-31), and the exposition holds one part of
  the store at a time (MET-32).

An exposition of 100,000 series over 100 names took 361 ms, between 340 and
382 ms, and held at most 42.8 KB of the store's memory. These are the
medians of five passes, a release build on a 4 vCPU Intel Xeon 2.10 GHz
Linux container with 15 GiB, while other builds shared the CPU:

```sh
cargo test --release -p tinystore --lib --features testing exposition_of_a_hundred_thousand -- --ignored --nocapture
```

## Export metrics and events

The command line now writes a store's metrics as Prometheus' text and a
stream's events as JSON lines, beside the program that holds the directory
([metrics export](../guides/cli/metrics.md#export-for-prometheus),
[events export](../guides/cli/events.md#export-a-stream)):

```sh
tinystore metrics ./data export --only-prefix shop_ --since 5m -o shop.prom
tinystore events ./data export audit --from 2026-11-01T00:00Z --to 2026-11-02T00:00Z > day.jsonl
```

- `metrics export` writes what [To Prometheus](#to-prometheus) writes.
- `events export` writes every event of the range, oldest first, the object
  that `list --json` prints. It reads a page at a time, so a stream of any
  length holds one page in memory.
- `-o` writes a file beside as `.part` and renames it once whole, so a
  reader never finds half of it.

## Times in one zone

A time printed for a person, and a time that `--from`, `--to` or `--at` is
given without its offset, is now in the zone `--tz` names
([Command line](../guides/cli/README.md)):

```sh
tinystore events ./data list audit --tz Asia/Kolkata --from 2026-11-25T09:00 --to 2026-11-25T18:00
TINYSTORE_TZ=utc tinystore logs ./data --since 1h
```

`--tz` takes an IANA name, `utc` or `local`. Without it, `TINYSTORE_TZ`
names the zone, and without either it is this machine's. `--json` prints
UTC whatever the zone.

## Changed names

- Bun, Node and Python: the text property `describe` of a database and of a
  transaction is `label`. `describe` is now the call of
  [What a statement answers](#what-a-statement-answers):

  ```ts
  db.describe // 0.12.0: 'sql app'
  db.label // 0.13.0: 'sql app'
  ```

  ```python
  db.describe  # 0.12.0: 'sql app'
  db.label  # 0.13.0: 'sql app'
  ```

  Go and Rust had no such property and change nothing.
